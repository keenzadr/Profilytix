# Profilytix — реализовано и дальнейший план

Дата: 6 ноября 2026 года.

По последнему указанию пользователя сейчас обновляем только документацию.
Задачи ниже запланированы, но их реализация в этой сессии не начата.

## Что уже реализовано

| Область | Возможности |
|---|---|
| Приложение | Локальное Windows-приложение на Python и PySide6, русский/английский интерфейс, сохранение выбора языка |
| Импорт | CSV, XLSX, XLS; распространённые кодировки; фоновое чтение; предпросмотр первых 100 строк |
| Колонки | Автоопределение и ручной выбор даты, выручки, расходов, суммы, категории; явный выбор описания для категоризации |
| Заголовки | Согласованная обработка пустых, повторяющихся и автоматически созданных названий при просмотре и анализе |
| Схемы | Сохранение, применение и удаление схем колонок через локальные настройки; проверка наличия нужных колонок |
| Метрики | Выручка, расходы, прибыль, число операций, средние значения и период анализа; работа с подписанной суммой |
| Категории | Разрез по исходным категориям и отдельная категоризация описаний по правилам RU/EN: маркетинг, продажи, аренда, зарплата, закупки, прочее |
| Графики | Час/день/неделя/месяц/год, начало недели, наведение с точными значениями, полноэкранный просмотр |
| Аномалии | IQR/Z-score и опциональный Isolation Forest; отметки на графике, подробности и наибольшее изменение категории |
| Прогноз | Скользящая средняя или линейный тренд; продолжение графика, числовая сводка и таблица в отчёте |
| Запас денег | Ввод текущего остатка, оценка срока до исчерпания и остатка через 30 дней; оценки не выдаются при операциях с суммой без корректной даты |
| Большие файлы | Прогресс чтения в байтах/строках, отмена анализа, просмотр всех строк страницами по 1 000 строк |
| Фоновые задачи | Безопасное закрытие окна и исправление зависания при завершении потоков |
| Отчёты | PDF, XLSX, HTML, PNG, CSV; краткий/подробный отчёт, RU/EN, прогноз, категории, аномалии и оценки запаса денег |
| Подготовка сборки | Конфигурация PyInstaller, скрипт Inno Setup, пример данных, журнал ошибок и автоматическая проверка ресурсов/экспорта |

Приложение остаётся локальным: без базы данных, облака, авторизации, платежей и LLM API.

## Дальнейший план

### 1. Встроенная справка по режимам — ближайшая задача

Цель: пользователь понимает выбор режима и ограничения результата без обращения к разработчику.

- [ ] Добавить кнопку справки рядом с выбором метода аномалий.
- [ ] Объяснить IQR и Z-score: что измеряют, чем отличаются, почему объединены в одном режиме.
- [ ] Объяснить Isolation Forest: быстро изолируемые редкие значения, отличие от статистических порогов.
- [ ] Описать фактические ограничения реализации: минимум 4 периода для правил и 8 для Isolation Forest, проверка каждого финансового ряда отдельно, зависимость результата от группировки.
- [ ] Объяснить направления поиска: всплески выручки/расходов, падения прибыли, оба направления для суммы.
- [ ] Дать простой числовой пример и пояснить, что аномалия не означает ошибку или мошенничество.
- [ ] Добавить справку по остальным режимам: группировка, прогноз, категоризация по описанию, текущий остаток и схемы колонок.
- [ ] Пояснить, что прогноз и запас денег основаны на прошлом, а текущий остаток вводится отдельно от прибыли.
- [ ] Объяснить различия краткого/подробного отчёта и содержание пяти форматов экспорта.
- [ ] Сделать справку доступной офлайн, на русском и английском, в текущем стиле PySide6.

Критерий готовности: справка открывается из соответствующих элементов интерфейса, соответствует коду, не меняет настройки/данные и проверена для обоих языков.

### 2. Развивать ML — следующий функциональный этап

Isolation Forest уже встроен. Следующий шаг — сравнить кандидатов на конкретной задаче,
сохранив локальную работу, существующий анализ и простые методы как контрольный вариант.
Ни одна из найденных моделей пока не установлена, не обучена и не проверена на наших файлах.

#### Кандидаты по результатам поиска 6 ноября 2026 года

| Кандидат | Готовые веса | Задача | Что потребуется |
|---|---|---|---|
| Chronos-Bolt Tiny, Amazon | Да, около 9 млн параметров; Apache-2.0 | Прогноз числовых временных рядов без начального обучения | Локальные веса, PyTorch/Chronos, замер CPU/RAM/размера сборки; дообучение возможно, но не первый шаг |
| TinyTimeMixer, IBM, r2.1 | Да, семейство от примерно 1 млн параметров; Apache-2.0 | Прогноз, в том числе нескольких рядов; дообучение | Выбор весов по длине истории и горизонту; r2.1 поддерживает дневные/недельные данные; PyTorch и дополнительная подготовка данных |
| CatBoost | Нет универсальных весов под наши операции; Apache-2.0 | Категоризация по тексту/категориальным признакам; прогноз по лагам | Собственное обучение; для категоризации нужны проверенные метки, для прогноза — временное разбиение |
| TF-IDF + линейный классификатор, scikit-learn | Нет универсальных весов под наши категории | Обучаемая категоризация описаний операций | Размеченные пары «описание → категория»; использует уже имеющийся стек |

TabPFN пока не выбран: лицензия кода и лицензии весов отличаются; актуальные семейства весов
в официальном репозитории перечислены с некоммерческими ограничениями. Для коммерческого
приложения нельзя предполагать, что лицензия кода автоматически разрешает использование любых весов.

#### Порядок ML-работ

- [ ] Выбрать первую задачу для сравнения. Предложение: улучшенный прогноз выручки/расходов; готовые веса Chronos-Bolt Tiny — первый кандидат для отдельного эксперимента.
- [ ] Подготовить набор временных рядов с понятными датами/частотой, явно различать отсутствующие периоды и нулевые операции.
- [ ] Организовать проверку по времени: обучение/контекст только из прошлого, оценка на более поздних периодах; исключить утечку будущих данных.
- [ ] Сравнить текущие методы, простой сезонный прогноз и выбранный ML-кандидат по MAE/WAPE, времени, памяти. При нулевом знаменателе WAPE не считать. Сравнивать одинаковые горизонты на нескольких временных срезах.
- [ ] Проверить работу на CPU, короткой истории, пропусках, отрицательных значениях и необычных расходах. Не обещать преимуществ до измерения.
- [ ] Если эксперимент показывает полезный результат, согласовать добавление конкретной зависимости/весов и способ офлайн-поставки перед изменением рабочего приложения. PyTorch-модели пока остаются кандидатами вне текущих зависимостей MVP.
- [ ] Подключить выбранный вариант как дополнительный режим с возвратом к простому методу при недостатке данных; указать метод и ограничения в интерфейсе/отчёте.
- [ ] Для обучаемой категоризации отдельно подготовить проверенную разметку; сравнить TF-IDF + линейный классификатор и CatBoost с текущими правилами по macro-F1 и ошибкам каждой категории. Не оценивать качество на тех же псевдометках, которыми учили модель.

Критерий готовности: воспроизводимое сравнение с исходным методом, измеренные ресурсы на Windows,
обоснованный выбор модели, сохранённая офлайн-работа и отсутствие регрессий. Исследование кандидатов
не означает, что внедрение новых зависимостей уже начато.

## Конкретные идеи из открытых приложений, отобранные в работу

Это предложения для реализации в Profilytix, а не решение переносить чужой код или менять стек.
Справка остаётся отдельной ближайшей задачей. Отобраны следующие дополнения:

### Приоритет 1: сравнение качества моделей — подход Orange Test and Score

- [ ] Создать воспроизводимую таблицу сравнения: текущий прогноз, сезонный простой метод, ML-кандидат; ошибка на будущем периоде, время расчёта, память.
- [ ] Использовать несколько последовательных временных срезов; обучать преобразования только на обучающей части.
- [ ] Для категорий показывать macro-F1 и ошибки каждой категории на проверенных метках; одинаковые данные проверки для всех кандидатов.
- [ ] При ухудшении качества или нехватке истории сохранять простой метод. Не называть ML более точным без измерения.

У нас уже есть выбор метода прогноза, но полноценного сравнения на отложенных периодах и
пользовательской сводки качества пока нет. Это конкретизирует ML-этап выше, а не создаёт отдельное обучение.
Критерий: результат сравнения можно повторить по сохранённому описанию данных/разбиения/настроек.

Источник подхода: https://orangedatamining.com/widget-catalog/evaluate/testandscore/

### Приоритет 1: диагностика данных до ML — развитие идеи Orange Data Info

- [ ] Показать пропуски и ошибки преобразования по выбранным колонкам: неверные даты, нераспознанные суммы, пустые описания/категории.
- [ ] Различать настоящий ноль, пустую сумму и нераспознанный текст; объяснять, как каждое состояние влияет на итоги.
- [ ] Показывать строки-примеры проблем и количество операций, исключённых из графика/прогноза.
- [ ] Отмечать возможные дубликаты, не удаляя их автоматически: одинаковые операции могут быть реальными.
- [ ] Включать краткую диагностику в отчёт и явно сообщать о недостаточной пригодности данных для модели.

Уже есть метаданные файла и защита оценки запаса денег от неверных дат. Полной диагностики
и прозрачного учёта ошибок преобразования пока нет. Содержание финансовых проверок — наше
предложение для Profilytix; Orange служит источником идеи отдельной сводки о наборе данных.
Критерий: пользователь видит, какие строки повлияли на доступность/достоверность результата.

Источник идеи: https://orangedatamining.com/widget-catalog/data/datainfo/

### Приоритет 2: исправление категорий и повторное применение — подход Actual Budget

- [ ] Разрешить исправить назначенную категорию одной или нескольких операций в рабочем результате, сохранив исходный файл.
- [ ] После исправления предлагать явное правило «такое описание/контрагент → категория»; разрешить изменить/удалить его.
- [ ] Установить понятный приоритет ручной правки, пользовательского правила, ML и стандартного правила; показывать источник назначения.
- [ ] Сохранять подтверждённые примеры в отдельный локальный CSV для обучения. Предсказания модели не считать подтверждённой разметкой.
- [ ] Для ML предусмотреть «не уверен / нужна проверка» с порогом, подобранным на проверочных данных.

Уже есть фиксированные правила RU/EN, но исправлений и пользовательских правил пока нет.
Критерий: исправление применяется повторно предсказуемо, а подтверждённая разметка отделена от предположений модели.
Для первого варианта достаточно локальных CSV/JSON, без добавления базы данных.

Источник: https://actualbudget.org/docs/budgeting/rules/

### Приоритет 2: переход от результата к операциям — идея FinanceOS

- [ ] Из категории или аномалии открывать отфильтрованный список участвующих исходных операций.
- [ ] Сохранять связь с исходным файлом/листом и номером записи, в том числе после очистки данных.
- [ ] Показывать используемые колонки, фильтры, период и исключённые строки.
- [ ] Давать выгрузку выбранных операций без изменения исходного файла.

Уже есть подробности аномалий и просмотр всех строк, но они пока не связаны интерактивной
расшифровкой. Идея взята из заявленного подхода FinanceOS «every number is clickable»;
его реализация и расчёты нами не проверены. Критерий: сумма операций расшифровки совпадает
с отображаемым показателем с учётом явно обозначенного округления и правил расчёта.

Источник идеи: https://github.com/shimentosh/financeos

### Приоритет 3: сравнение периодов и вклад категорий — подход Actual Budget Reports

- [ ] Добавить выбор текущего и сравниваемого периода, а не только частоты группировки.
- [ ] Для выручки/расходов/прибыли показать абсолютное изменение и процент при корректной ненулевой базе.
- [ ] Показать вклад категорий в изменение расходов/прибыли и переход к операциям.
- [ ] Явно отмечать неполный период, разную длину и отсутствующие данные; не приписывать неизвестные дни нулевым операциям.

Уже есть отдельные текстовые выводы о динамике, но произвольного сравнения периодов и
расшифровки вклада категорий пока нет. Критерий: сумма вкладов объясняет общее изменение,
а несопоставимые периоды обозначены до интерпретации результата.

Источник: https://actualbudget.org/docs/reports/

Полный бухгалтерский учёт GnuCash/KMyMoney, банковская синхронизация, инвестиционные портфели,
сервер FinanceOS и визуальный конструктор всех ML-процессов Orange в работу не отобраны.

- [ ] Проверить PyOneDark на Python 3.12+ и используемой версии PySide6 в отдельном небольшом прототипе.
- [ ] Проверить масштабирование Windows 100/125/150%, кириллицу, управление клавиатурой,

- [ ] После проверки использовать только нужные части оболочки и виджетов, сохраняя нашу
      аналитику, загрузчики, фоновые задачи и слой отчётов.

PyOneDark — готовый каркас PySide6, но его совместимость с текущим окружением ещё не
проверена. Если проверка обнаружит существенные проблемы, запасной вариант — существующие
Qt Widgets с Qt-Material (BSD-2-Clause) и собственной навигацией. Fluent Widgets не выбран:
его лицензирование требует отдельного решения для будущего распространения продукта.

Actual Budget используется как визуальный и поведенческий ориентир для карточек показателей,
фильтров и финансовых отчётов. Его frontend-код не переносится: Profilytix остаётся нативным
PySide6-приложением, без web-стека.

Источники:

- PyOneDark: https://github.com/Wanderson-Magalhaes/PyOneDark_Qt_Widgets_Modern_GUI
- Actual Budget: https://actualbudget.org/
- Qt-Material (запасной вариант): https://github.com/UN-GCPDS/qt-material

### Предлагаемая структура приложения

| Раздел | Содержание |
|---|---|
| Обзор | Карточки выручки, расходов и прибыли, график динамики, ключевые выводы; позднее — сравнение периодов |
| Данные | Загрузка, предпросмотр и все строки, выбор колонок, сохранённые схемы, диагностика качества |
| Категории | Исходные и определённые по описанию категории; позднее — исправления и пользовательские правила |
| Аномалии и прогноз | Выбор метода, результаты аномалий, прогноз, текущий остаток и запас денег; позднее — сравнение качества моделей |
| Отчёты и справка | Экспорт, язык и подробность отчёта, объяснения методов, примеры и ограничения |

Экраны показывают фактически реализованные возможности. Будущие функции из таблицы
подключаются по мере готовности; не создавать кнопки, обещающие несуществующий результат.

### Порядок переноса

- [ ] Подготовить компактный макет разделов, навигации, фильтров и карточек; согласовать
      внешний вид до переноса рабочего окна.
- [ ] Перенести оболочку и навигацию, сохранив выбранный файл, колонки, язык и результаты
      при переходах между разделами.
- [ ] Перенести существующие элементы по разделам без изменения финансовых формул.
- [ ] Добавить общую индикацию загрузки/анализа/экспорта, доступность отмены и понятные
      состояния «нет файла», «нет результатов», «недостаточно данных», «ошибка».
- [ ] Согласовать оформление светлой/тёмной темы, таблиц, графиков, подписей и кнопок;
      проверить контраст и читаемость длинных русских названий.
- [ ] Встроить запланированную справку рядом с выбором соответствующих режимов.
- [ ] Проверить все прежние сценарии: импорт CSV/XLSX/XLS, схемы колонок, категории,
      аномалии, прогноз, запас денег, страницы таблицы, отмена, безопасное закрытие,
      RU/EN и пять форматов экспорта.
- [ ] Повторить автоматические проверки и ручную приёмку; отдельно проверить новую
      оболочку в Windows-сборке, когда сборочные инструменты будут доступны.

Критерий готовности: приложение имеет согласованную навигацию и финансовые экраны,
сохраняет состояние между разделами, корректно масштабируется на Windows и полностью
сохраняет уже работающую функциональность. Тема оформления сама по себе не считается
готовым переносом интерфейса.

Изменение стека, добавление базы/облака/авторизации/платежей/LLM API в этот план не входит.

## Порядок работы

Сначала проверить совместимость оболочки и согласовать макет. Далее обновить интерфейс
и встроить справку, сохраняя существующие функции. Затем — ML-эксперименты и выбор модели,
проверка и исправления, первый запуск и Windows-сборка. Подготовку данных и сравнение моделей
можно выполнять независимо от визуального переноса.
На ML-этапе приоритет 1 имеют диагностика входных данных и воспроизводимое сравнение моделей;
затем идут исправление категорий/расшифровка операций, после них — сравнение периодов.
Если ручная проверка обнаруживает ошибку в расчётах или стабильности, её исправление получает приоритет перед следующими задачами.
